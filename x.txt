1. Introduction — Why do we need I3C?

📘 Wiki Content

Introduction

I3C (Improved Inter-Integrated Circuit) is a communication protocol developed by MIPI Alliance for connecting sensors, controllers, and other peripheral devices using a two-wire interface.

I3C was designed to address several limitations of the widely used I²C (Inter-Integrated Circuit) protocol while maintaining compatibility with existing I²C devices.

Modern embedded systems may contain a large number of peripheral devices such as sensors, power-management devices, controllers, and other components. As the number of devices increases, requirements such as higher communication speed, lower power consumption, efficient interrupt handling, dynamic device management, and reduced pin count become increasingly important.

Traditional I²C has several limitations in these areas. I3C addresses these limitations while retaining the simplicity of a two-wire bus.

Why do we need I3C?

The major motivations for introducing I3C are:

* Higher data throughput: I3C provides significantly higher communication speeds than traditional I²C.
* Lower power consumption: I3C makes greater use of push-pull signaling, reducing the dependence on pull-up resistors and enabling more efficient communication.
* In-Band Interrupts (IBI): Devices can notify the controller using the same two-wire bus instead of requiring a dedicated interrupt GPIO for every device.
* Dynamic Address Assignment: I3C devices can be dynamically assigned addresses by the controller, simplifying device discovery and configuration.
* Hot-Join: Devices can request to join an already-active I3C bus without requiring the entire system to be restarted.
* Common Command Codes (CCC): I3C defines standardized commands for common bus-management and device-management operations.
* I²C coexistence: I3C is designed to allow supported legacy I²C devices to coexist on the same bus.
* Two-wire interface: Like I²C, I3C uses the SDA and SCL signals, helping minimize the number of required pins and physical connections.

I²C vs I3C — The Motivation

The key idea behind I3C is not to completely replace I²C with an unrelated protocol, but to provide a more capable two-wire interface that addresses the requirements of modern systems while preserving interoperability with legacy I²C devices.

In simplified terms:

I²C provides a simple two-wire communication mechanism, while I3C builds on that concept to provide higher performance, better power efficiency, device management, and interrupt capabilities.

2. 🎤 Speech for the Session

You can say something like this:

“Before we understand how I3C works, the first question we should ask is — why do we need I3C when we already have I²C?”

“I²C has been around for a very long time and is still widely used. It gives us a simple two-wire interface using SDA and SCL, and we can connect multiple devices to the same bus.”

“However, as embedded systems became more complex, the requirements also increased. We started having more sensors and peripheral devices, and these devices needed higher communication speed, lower power consumption, better interrupt mechanisms, and easier device management.”

“Traditional I²C has limitations in several of these areas. For example, communication speed is limited compared with newer interfaces. Also, I²C devices commonly require separate GPIO lines when they need to generate interrupts.”

“This is where I3C comes in. I3C keeps the basic idea of a two-wire bus, but adds features such as higher-speed communication, in-band interrupts, dynamic address assignment, hot-join, and standardized common commands.”

“Another important point is that I3C was designed with backward compatibility in mind. Supported legacy I²C devices can coexist with I3C devices on the same bus.”

“So, if I had to summarize the motivation for I3C in one sentence: I3C tries to provide the simplicity of a two-wire interface while offering much of the performance and functionality required by modern embedded systems.”

Problem #5 — Device Management

Suppose the controller wants to perform common operations such as:

* Discover a device
* Get device information
* Assign an address
* Enable/disable certain features
* Manage the bus

You don’t want every manufacturer to invent a completely different command format.

I3C therefore defines CCC — Common Command Codes.

Think of CCC as a standard vocabulary between the controller and I3C devices.

One correction worth remembering

Don’t describe I3C simply as “a faster version of I²C.”

That’s technically too simplistic.

A better description is:

I3C is a new two-wire communication protocol that builds upon concepts from I²C while introducing higher-speed operation, dynamic addressing, in-band interrupts, standardized device-management commands, and other features for modern systems.

That wording will sound much stronger in an office technical session.
