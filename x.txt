🧠 Understanding — I3C vs I²C

Think of I3C as an attempt to solve the problems that appear when an I²C bus has to support more devices, more data, lower power, and more complex system behavior.

1. Why is I3C faster?
I²C primarily uses open-drain signaling. A device can pull the line LOW, but to make it HIGH, the pull-up resistor has to bring the signal back up. The speed of this rising edge depends on the pull-up resistor and the capacitance of the bus. As the bus gets larger, this becomes a limitation. I3C uses push-pull signaling during appropriate parts of communication, allowing the device to actively drive HIGH as well as LOW. This gives much faster transitions and therefore enables higher-speed communication.

2. Why does I3C have dynamic addressing?
With I²C, devices generally have predefined addresses. Imagine you have two identical sensors that both want address 0x48. You have an address conflict. Some I²C devices provide hardware pins or configuration mechanisms to change the address, but that’s not universal. I3C provides a standardized mechanism where the controller can discover devices and assign dynamic addresses. This is primarily done through ENTDAA (Enter Dynamic Address Assignment).

3. Why does I3C have IBI?
Imagine 8 sensors connected to a processor. With traditional I²C, each sensor might need a separate GPIO interrupt line:

That’s a lot of pins and PCB routing. I3C allows a target to say “I need the controller’s attention” using the I3C bus itself. That’s IBI — In-Band Interrupt. The interrupt information travels in-band, meaning through the communication interface rather than through a separate physical GPIO.

4. Why does I3C have CCC?
In I²C, the basic bus protocol is standardized, but what a device-specific command means is usually defined by that device’s specification. I3C introduces Common Command Codes (CCC) so that common bus/device-management operations have standardized commands. For example, the controller can use standard commands to obtain device information or manage addresses. Think of CCC as a common language for bus management.

5. Why does I3C have Hot-Join?
Normally, the controller initializes the bus and discovers the devices that are present. But what if an I3C device becomes available after the bus is already running? I3C provides Hot-Join, allowing that target to request to join the active bus. The controller can then handle the device and assign it an address as required.

6. Why can I3C coexist with I²C devices?
I²C already exists in an enormous number of systems. Requiring every existing peripheral to be replaced would make I3C difficult to adopt. Therefore, I3C was designed so that supported legacy I²C devices can coexist on the same physical bus with I3C devices.

7. Why is power efficiency better?
With I²C’s open-drain signaling, when a device holds a line LOW, current flows through the pull-up resistor. I3C’s push-pull operation reduces reliance on this resistive pull-up behavior during normal high-speed transfers. Combined with faster transfers, this can improve overall bus power efficiency.

8. Why does I3C support multiple controllers?
Some systems can have more than one device capable of controlling the bus. I3C defines roles such as Primary Controller and Secondary Controller and mechanisms for controller handoff. This makes the bus architecture more flexible. However, for your basic understanding, think of the common case as one Primary Controller + multiple Targets.
